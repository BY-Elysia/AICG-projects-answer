| 层级 | 结果与证据 | 能证明的内容 |

## 已修正的问题

- MCP 连接在 OpenCode 会话创建/恢复后异步完成，过早发送提示会缺少工具；适配器现在等待 MCP ready。
- 源文件路径同时接受 `model.py` 和 `source/model.py`，避免工具使用者意外创建重复层级；重建器严格保留下载包层级，避免旧文件覆盖主文件。
- 会话选择采用稳定控件状态，模型预览不再意外显示 Streamlit 内部对象。
- STEP 验收在仅包含 STEP 的新目录、新容器中执行，生成的 Python 不参与验收导入路径。
- 每个会话用文件锁阻止同时运行两轮；状态文件原子写入。

初版安装板真实模型曾出现主文件路径错误，读取执行反馈后自行改写并成功重试。这是自然发生的工具失败；`protocol_results.json` 的首次失败则是明确注入的测试错误，两者分别记录。

## 限制与复现

查看各 `live_*.json` 的 `independent_fixture_check.passed`；只有非空 `delivered` 且独立检查通过才算成功。完整过程保存在本地 `workspace/<session>/events.jsonl` 和 `state.json`，这些含用户输入的运行文件不纳入默认提交。

初次镜像已从 Python 基础镜像构建成功，并按实际环境冻结依赖。再次按完整锁文件从头下载时大包下载缓慢，本次复用已安装相同版本的镜像更新 worker；实际依赖已逐项核对锁文件。最终 Dockerfile 的全新锁文件下载构建尚未完成复测。Windows/Linux 的宿主安装流程未验证。

独立检查支持单一有效闭合实体、包围盒、体积、轴对齐平面和 Z 轴圆柱面。没有通用几何语义证明、自动视觉验收、强度或制造验证；Pi/Claude harness 迁移说明仅为接口设计，适配器未实现。

脚本化协议测试可复现：停止普通 demo，终端 A 运行 `uv run python tests/fake_model.py`；终端 B/C 设置 `LLM_BASE_URL=http://127.0.0.1:8097/v1`、`LLM_MODEL=demo-test`、`LLM_API_KEY=fixture`，B 运行 `manage.py serve`，C 运行 `scripts/verify_protocol.py`（两者均用 `uv run python`）。测试后停止 B/A，清除这三个临时环境变量，正常启动即可恢复 `.env` 模型配置。该 fixture 不访问外部模型服务。

### 简化需求流程与运行控制

- 需求明确后直接记录合同并执行；仅对不明确的条件提问，移除独立确认卡片及旧宿主确认指令的聊天展示。
- 主按钮使用浅底深字；运行中显示动态状态、计时与停止按钮。停止请求传给 OpenCode，同时离线执行容器轮询取消标记并清理。
- 回归覆盖直接记录需求、停止调用 harness 并保留消息、运行界面显示停止入口且无确认卡片。17 项测试通过。

### 逐条工具调用展示

- 参考源平台 ToolCard，按消息/分片的实际顺序呈现文本与每次工具调用，不再合并为步骤总数。
